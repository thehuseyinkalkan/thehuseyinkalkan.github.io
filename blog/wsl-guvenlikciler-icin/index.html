Windows'un İçindeki Linux: Güvenlikçiler için WSL'e Sıcak Bir Giriş

WSL nedir, WSL 1 ile 2 arasındaki fark, Kali kurulumu, reverse shell'leri bozan ağ tuzağı ve günlük işleri kolaylaştıran küçük ayarlar.

Bir zamanlar Windows kullanan bir güvenlikçinin önünde iki seçenek vardı: ya bilgisayarı ikiye bölüp her seferinde yeniden başlatmak (dual boot), ya da birkaç GB RAM'i yiyip yavaş açılan bir sanal makineyle yaşamak. WSL (Windows Subsystem for Linux) üçüncü bir yol açtı: Linux'u Windows'un içinde, bir uygulama açar gibi çalıştırmak.

Bu yazıda WSL'in ne olduğunu, Kali'yi nasıl birkaç dakikada kurabileceğini ve en önemlisi, pentest yaparken insanı saatlerce uğraştıran ağ tuzağını anlatacağım. Görsellerdeki terminal çıktıları kendi makinemden.

WSL tam olarak ne?

Kısaca: Windows'ta, Linux programlarını gerçekten çalıştırmanın resmi yolu. İki sürümü var ve aralarındaki fark, neyin çalışıp neyin çalışmayacağını belirliyor:

  • WSL 1, Linux sistem çağrılarını Windows çekirdeğine çeviren bir katmandır. Gerçek bir Linux çekirdeği yoktur; bu yüzden ham soket (raw socket) gibi düşük seviyeli işler sınırlıdır.
  • WSL 2, Hyper-V altyapısı üzerinde bir saniyede açılan hafif bir sanal makinede gerçek Linux çekirdeği çalıştırır. sudo nmap -sS ile SYN taraması, Docker, kernel modülü gerektiren araçlar burada çalışır.

Güvenlik işleri için cevap net: WSL 2. Bugün wsl --install zaten varsayılan olarak onu kuruyor.

5 dakikada kurulum

Yönetici olarak açtığın bir PowerShell yeterli:

# WSL'i kur (ilk seferde yeniden başlatma isteyebilir)
wsl --install

# Kurulabilecek dağıtımları gör, Kali'yi ekle
wsl --list --online
wsl --install -d kali-linux

Kali WSL'de neredeyse boş gelir; araçları sen seçersin. Klasik araç setini istiyorsan:

sudo apt update && sudo apt full-upgrade -y
sudo apt install -y kali-linux-default     # nmap, burp, impacket, metasploit...
# ya da daha hafifi:
sudo apt install -y kali-linux-headless

Grafik arayüzlü araçlar (Burp, Wireshark) için ekstra bir şey gerekmez: Windows 11'deki WSLg sayesinde Linux pencereleri Windows masaüstünde normal bir uygulama gibi açılır. Tam bir Kali masaüstü istersen sudo apt install -y kali-win-kex ve ardından kex --win -s.

İçeride hayat nasıl?

En tatlı kısmı şu: iki dünya birbirini görüyor.

  • Windows dosyaları Linux'ta: C:\ sürücüsü /mnt/c altında.
  • Linux dosyaları Windows'ta: Gezgin'in adres çubuğuna \\wsl.localhost\kali-linux yaz, ya da Linux'tayken explorer.exe . çalıştır.
  • Programlar karşılıklı: bash'ten powershell.exe, notepad.exe; PowerShell'den wsl nmap -sV 10.10.10.5.

Güvenlikçinin asıl tuzağı: ağ

Görseldeki 172.31.45.208 adresine dikkat. Varsayılan modda WSL 2, Windows'un arkasında kendi küçük NAT ağında yaşar. Dışarı bağlanmak sorun değil; ama içeri gelen bağlantılar (reverse shell!) WSL'e ulaşmaz.

Klasik senaryo: HTB/PG VPN'ini Windows'ta açarsın, Kali'de nc -lvnp 443 dinlersin, hedefe LHOST olarak VPN IP'ni verirsin… ve hiçbir şey gelmez. Bağlantı Windows'a çarpar, kimse dinlemediği için düşer. İki temiz çözüm var:

Çözüm 1: VPN'i WSL'in içinde çalıştır

sudo apt install -y openvpn
sudo openvpn lab.ovpn          # tun0 artık Linux'ta
ip -4 addr show tun0           # LHOST olarak bu IP'yi kullan

Tünel, dinleyicinin olduğu yerde bittiği için NAT modunda bile çalışır. En az ayar isteyen yol bu.

Çözüm 2: Mirrored ağ modu

Windows 11'de WSL'e Windows'un ağ arayüzlerini aynen kullandırabilirsin. Kullanıcı klasöründe %UserProfile%\.wslconfig dosyasını oluştur:

[wsl2]
networkingMode=mirrored
memory=6GB        # isteğe bağlı: WSL'in RAM üst sınırı
processors=4      # isteğe bağlı

Sonra wsl --shutdown ile WSL'i kapatıp yeniden aç. Artık Kali, Windows'un tun0 adresini de görür. Gelen bağlantıları Hyper-V güvenlik duvarı engelleyebilir; her şeyi açmak yerine sadece dinleyici portuna izin ver (yönetici PowerShell):

New-NetFirewallHyperVRule -Name WSL-443 -DisplayName "WSL reverse shell 443" `
  -Direction Inbound -VMCreatorId '{40E0AC32-46A5-438A-A0B2-2B479E8F2E90}' `
  -Protocol TCP -LocalPorts 443

Kısa yol: Lab'da en az sürprizi Çözüm 1 yaşatır. Mirrored mod ise Windows'taki araçlarla (ör. Burp'ün Windows sürümü) WSL'i aynı ağda buluşturmak istediğinde güzel.

Küçük ama tatlı ayarlar

  • Çalışma dosyalarını Linux tarafında tut (~/). /mnt/c üzerinden dosya işlemleri belirgin şekilde yavaştır; ayrıca exploit ve payload'larını Windows klasörlerinde tutmak, Defender'ın onları "bulup" silmesine davetiye çıkarır.
  • Bir şeyler tuhaflaşınca: wsl --shutdown. Bilgisayarı yeniden başlatmanın WSL'deki karşılığı, iki saniye sürer.
  • Windows Terminal'de Kali'yi varsayılan profil yap; sekmeler ve bölünmüş paneller tmux'a alışık olmayanlar için bile rahat.
  • VS Code'u WSL eklentisiyle kullan: Kali'de bir klasördeyken code . yazınca editör Windows'ta açılır ama dosyalar ve terminal Linux'ta kalır.
  • Yedek al: wsl --export kali-linux kali-yedek.tar ile tüm kurulumu tek dosyada saklayabilir, başka makinede wsl --import ile geri açabilirsin.

WSL'in yetmediği yerler

  • Kablosuz testler: Wi-Fi adaptörünü monitor modda kullanmak için USB'yi WSL'e aktarmak (usbipd-win) ve uygun sürücüyü derlemek gerekiyor. Bu iş için ayrı bir Kali kurulumu ya da VM daha az uğraştırır.
  • Sınav ortamı: OSCP gibi sınavlarda OffSec'in önerdiği ortam Kali sanal makinesi. WSL'i günlük işler ve lab için düşün; sınav günü sürpriz istemezsin.
  • Kurumsal cihazlar: EDR ve şirket politikaları WSL'i kısıtlayabilir ya da izleyebilir. İş bilgisayarında kullanmadan önce kuralları kontrol et.

WSL, "Linux mu Windows mu?" sorusunu "ikisi birden" diye cevaplıyor. Ağ tuzağını bir kez çözdükten sonra, günlük pentest notlarından lab makinelerine kadar çoğu işi tek bir bilgisayarda, yeniden başlatmadan yapabiliyorsun. Linux Inside Windows: A Friendly WSL Guide for Security Folks

What WSL is, WSL 1 vs 2, installing Kali, the networking trap that breaks reverse shells, and small tweaks that make daily work easier.

Not long ago, a security person on Windows had two choices: split the laptop in two and reboot every time (dual boot), or live with a virtual machine that eats a few GB of RAM and takes ages to start. WSL (Windows Subsystem for Linux) opened a third way: run Linux inside Windows, as easily as opening an app.

In this post I cover what WSL is, how to get Kali running in a few minutes and, most importantly, the networking trap that costs people hours during pentests. The terminal output in the images comes from my own machine.

So what exactly is WSL?

In short: the official way to really run Linux programs on Windows. There are two versions, and the difference decides what will and will not work:

  • WSL 1 is a layer that translates Linux system calls for the Windows kernel. There is no real Linux kernel, so low-level work such as raw sockets is limited.
  • WSL 2 runs a real Linux kernel in a lightweight VM on the Hyper-V platform that starts in about a second. SYN scans with sudo nmap -sS, Docker and tools that need kernel features work here.

For security work the answer is clear: WSL 2. Today wsl --install installs it by default anyway.

Installing it in 5 minutes

An administrator PowerShell is all you need:

# Install WSL (the first run may ask for a reboot)
wsl --install

# See the available distributions, add Kali
wsl --list --online
wsl --install -d kali-linux

Kali on WSL comes almost empty; you pick the tools. For the classic toolset:

sudo apt update && sudo apt full-upgrade -y
sudo apt install -y kali-linux-default     # nmap, burp, impacket, metasploit...
# or something lighter:
sudo apt install -y kali-linux-headless

GUI tools (Burp, Wireshark) need nothing extra: thanks to WSLg on Windows 11, Linux windows open on the Windows desktop like normal apps. If you want a full Kali desktop, run sudo apt install -y kali-win-kex and then kex --win -s.

What life looks like inside

The sweetest part: the two worlds can see each other.

  • Windows files from Linux: the C:\ drive lives under /mnt/c.
  • Linux files from Windows: type \\wsl.localhost\kali-linux into the Explorer address bar, or run explorer.exe . from Linux.
  • Programs both ways: powershell.exe or notepad.exe from bash; wsl nmap -sV 10.10.10.5 from PowerShell.

The real trap for security folks: networking

Look at the 172.31.45.208 address in the image. By default WSL 2 lives in its own small NAT network behind Windows. Connecting out is fine, but incoming connections (reverse shells!) do not reach WSL.

The classic scenario: you start the HTB/PG VPN on Windows, listen with nc -lvnp 443 in Kali, give the target your VPN IP as LHOST… and nothing arrives. The connection hits Windows, nobody listens there, and it is dropped. There are two clean fixes:

Fix 1: run the VPN inside WSL

sudo apt install -y openvpn
sudo openvpn lab.ovpn          # tun0 now lives in Linux
ip -4 addr show tun0           # use this IP as LHOST

The tunnel ends where your listener is, so this works even in NAT mode. It is the path with the least configuration.

Fix 2: mirrored networking mode

On Windows 11 you can let WSL use Windows' network interfaces as they are. Create %UserProfile%\.wslconfig in your user folder:

[wsl2]
networkingMode=mirrored
memory=6GB        # optional: RAM cap for WSL
processors=4      # optional

Then stop WSL with wsl --shutdown and start it again. Kali now sees Windows' tun0 address too. Incoming connections can be blocked by the Hyper-V firewall; instead of opening everything, allow only your listener port (administrator PowerShell):

New-NetFirewallHyperVRule -Name WSL-443 -DisplayName "WSL reverse shell 443" `
  -Direction Inbound -VMCreatorId '{40E0AC32-46A5-438A-A0B2-2B479E8F2E90}' `
  -Protocol TCP -LocalPorts 443

Shortcut: in labs, Fix 1 gives the fewest surprises. Mirrored mode is nice when you want tools on Windows (for example the Windows build of Burp) and WSL on the same network.

Small but sweet tweaks

  • Keep your working files on the Linux side (~/). File operations through /mnt/c are noticeably slower, and keeping exploits and payloads in Windows folders invites Defender to "find" and delete them.
  • When things get weird: wsl --shutdown. It is WSL's version of rebooting the computer, and it takes two seconds.
  • Make Kali the default profile in Windows Terminal; tabs and split panes are comfortable even if you are not used to tmux.
  • Use VS Code with the WSL extension: type code . in a Kali folder and the editor opens on Windows while files and the terminal stay in Linux.
  • Back it up: wsl --export kali-linux kali-backup.tar stores the whole install in one file, and wsl --import restores it on another machine.

Where WSL is not enough

  • Wireless testing: using a Wi-Fi adapter in monitor mode means passing USB into WSL (usbipd-win) and building the right driver. A separate Kali install or VM is less hassle for this.
  • Exam environment: for exams like the OSCP, the environment OffSec recommends is a Kali virtual machine. Think of WSL for daily work and labs; you do not want surprises on exam day.
  • Corporate devices: EDR and company policy may restrict or monitor WSL. Check the rules before using it on a work laptop.
